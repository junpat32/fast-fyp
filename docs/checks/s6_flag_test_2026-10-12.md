# S6 flag test (2026-10-12)

**What:** the three behavioural flags of spec §9, added to the prototype
(`proto_s6_2026-10-12.py`, 3,000 users, seeds 20261009 and 7). Data-level only;
no model trained. Hidden traits were used **only to audit** the flags, as `latent.parquet`
allows.

**Readings used** (the spec wording was ambiguous; to be written into §9):
1. Budget = 0.95 × median of the **previous** 3 months' total spending.
2. Overrun = **total** spending > budget.
3. CV uses the **sample** standard deviation.
4. Saved = income − spending − debt payments − family support − shocks (observable).
5. Savings-rate change = saved ÷ income vs the previous month.

## Results (seed 20261009; seed 7 within ±0.5 points)

| Flag | Fires (S6: 5–30%) | By type emp / gig / stu | Validity: riskiest vs safest quarter of the hidden trait |
|---|---|---|---|
| Impulsivity | 6.8% ✓ | 6.6 / 7.1 / 7.6% | 16.9% vs 0.6% → **lift ×27** (strong) |
| Overconfidence | 8.0% ✓ | 6.4 / **13.1** / 10.4% | 9.5% vs 6.4% → lift ×1.5 (**weak**) |
| Overconfidence, smoothed + calm months | 18.7% ✓ | 16 / 27 / 23% | lift ×1.3 (no better) |
| Delayed correction (as specified) | **3.5% ✗** | 4.4 / 1.4 / 1.0% | lift ×1.3 (weak) |
| Delayed correction, fixed | 8.6% ✓ | 9.2 / 8.2 / 6.0% | lift ×1.5 (weak) |

## Diagnosis

- **Impulsivity works.** The variation test does nearly all the work. The overrun part
  is true in 71% of person-months (the budget is set below the median by design), so it adds little.
- **Delayed correction as written fails** because ordinary month-to-month noise in
  discretionary spending looks like a "5% cut" most months. The fix measures the cut on
  a 2-month average against the previous 3 months, and narrows "pressure" to Red or
  cushion < 1 (plain Yellow is common and not a warning on its own).
- **Overconfidence and delayed correction are weakly valid** even where the truth is
  known. The cause is in the generator, not only the flags: the two traits leave too
  small a footprint compared with noise. Overconfidence only scales the savings target
  (×1.0–1.7), and targets are recomputed mechanically each month, so "not lowering the
  goal" isn't behaviour at all. A correction is a one-month cut of 10–25%, which spending
  noise of up to ±50% hides. Overconfidence also fires twice as often for gig workers,
  which is income volatility being mistaken for overconfidence (a fairness concern for
  app explanations).

## Handling (applied 2026-10-12, Patrick's decision, D-41; spec v0.6)

1. Adopt the delayed-correction fix in §9 (passes S6, consistent across user types).
2. Write readings 1–5 into §9.
3. Generator (§9, not frozen): give the traits a realistic footprint. Overconfident users
   keep their goal after missing it (goal stickiness, probability = `ovc`), and a correction
   lasts 3 months instead of 1. Assumption; re-measured in T-05.
4. Add **S14 (flag validity)** to §14 as a pre-registered *decision rule*: a flag whose
   lift is below ×2 stays an ML feature but is **not shown to users** as an explanation.
   This decides in advance what happens if a flag is weak, so nothing is chosen after the fact.
